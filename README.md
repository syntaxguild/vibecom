# Desk Companion Bot

เฟิร์มแวร์ C++ สำหรับ ESP32, Arduino Framework, PlatformIO และ Wokwi Simulator ดวงตาทึบไม่มีวงกลมหรือจุดไฮไลต์ภายในตา ไม่มีระบบเสียง และลูบหัวผ่านเซ็นเซอร์สัมผัส TTP223

![ภาพประกอบดวงตาทึบทั้งสี่อารมณ์ ไม่มีวงกลมไฮไลต์ภายในตา](docs/eye-preview.svg)

ภาพประกอบแสดงรูปตาหลัก แอนิเมชันจริงยังมีกะพริบ กลอกตา และขยับตามอารมณ์

## เริ่มจำลองใน VS Code

1. เปิดโฟลเดอร์นี้ใน VS Code และติดตั้งส่วนเสริม **PlatformIO IDE** กับ **Wokwi Simulator** ตามคำแนะนำของ workspace
2. รอ PlatformIO ติดตั้งเครื่องมือให้เสร็จ แล้วกด **PlatformIO: Build** (เครื่องหมายถูกที่แถบล่าง) หรือรัน `pio run -e esp32dev` ใน PlatformIO terminal
3. กด `F1` → **Wokwi: Start Simulator** หาก Wokwi ขอเปิดใช้งาน license ให้ทำตามหน้าจอของส่วนเสริมก่อน
4. คลิก HC-SR04 แล้วเลื่อนค่า Distance เพื่อทดสอบ เริ่มต้นที่ 100 cm
5. เลื่อนสวิตช์ **TTP223 OUT (simulation)** ไปทางขวาเพื่อจำลองการแตะหัว (`HIGH`) และเลื่อนกลับซ้ายเพื่อปล่อย (`LOW`) สวิตช์นี้จำลองเฉพาะสัญญาณ OUT ของเซ็นเซอร์ ไม่ใช่การจำลองความจุไฟฟ้าหรือโมดูล TTP223 จริง
6. ดูระยะทาง โหมด มุมเซอร์โว และ FPS ใน Serial Monitor ของ Wokwi ที่ 115200 baud

Wokwi ใช้ `.pio/build/esp32dev/firmware.bin` และ `firmware.elf` ซึ่งได้จากการ Build ต้อง Build ใหม่เมื่อแก้ไขโค้ด แล้วเริ่ม Simulator ใหม่

## พฤติกรรม

| โหมด / เงื่อนไข | ดวงตา OLED | เซอร์โว |
| --- | --- | --- |
| Idle: มากกว่า 50 cm | ตาแคปซูลทึบ กลอกตามองรอบตัวแบบนุ่มนวล กะพริบแบบยุบแล้วเปิด | คอขยับตามสายตาเล็กน้อย |
| Idle / Sleepy: ไม่มีปฏิสัมพันธ์เกิน 10 วินาที | ตาปรือครึ่งหนึ่ง มี Zzz ลอยขึ้น | คอกลับ 90° |
| Happy: 15–50 cm รวมขอบทั้งสองด้าน | ตาโค้งยิ้ม หัวใจและดาวลอยข้างแก้ม | ส่ายคออย่างนุ่มนวล |
| Angry: น้อยกว่า 15 cm | ตาถูกตัดขอบเป็นคิ้วขมวด สั่นเล็กน้อย มีเครื่องหมายตกใจ | หันหนีไป 180° |
| Love: เซ็นเซอร์สัมผัส GPIO 4 เป็น HIGH มีลำดับความสำคัญสูงสุด | ตาหัวใจทึบเต้นเบา ๆ พร้อมแก้ม | ดุ๊กดิ๊กคอเบา ๆ |
| ไม่มี echo ภายใน 30 ms | กลับ Idle พร้อมรายงาน no echo หากไม่ได้อยู่ใน Love | คอกลับขยับตาม Idle |

Love ค้างต่ออีก 1.2 วินาทีหลังยืนยันการปล่อยสัมผัส สัญญาณเซ็นเซอร์ต้องนิ่ง 25 ms จึงเปลี่ยนสถานะ การขยับวัตถุห่างจากระยะอ้างอิงอย่างน้อย 4 cm จะปลุกจากอาการง่วง รวมถึงการเข้าใกล้ในระยะ 50 cm หรือการลูบหัว ทุกโหมดไม่มีการสร้างเสียง และถอด buzzer รวมถึงสาย GPIO 25 ออกจากวงจรแล้ว

## ลูบหัวด้วยเซ็นเซอร์จริง

ใช้โมดูล **TTP223 capacitive touch** ติดแผ่นสัมผัสบริเวณหัว แล้วต่อดังนี้:

| TTP223 | ESP32 |
| --- | --- |
| VCC | 3V3 |
| GND | GND ร่วม |
| OUT / I/O | GPIO 4 |

ตั้งโมดูลเป็น **Direct / Momentary + Active HIGH**: แตะแล้ว OUT เป็น HIGH และปล่อยแล้วเป็น LOW ห้ามตั้ง Toggle เพราะจะค้างสถานะหลังปล่อย ตรวจตำแหน่งจัมเปอร์ตามคู่มือโมดูลที่ใช้ เพราะแต่ละบอร์ดอาจต่างกัน จ่ายไฟ 3.3V เพื่อให้สัญญาณ OUT อยู่ในระดับเดียวกับ ESP32 และปล่อยแผ่นสัมผัสว่างตอนเปิดเครื่องอย่างน้อย 1 วินาทีให้เซ็นเซอร์ปรับค่าเริ่มต้น

โค้ดใช้ `digitalRead()` กับ `INPUT_PULLDOWN` จึงใช้เฟิร์มแวร์เดียวกันได้ทั้งเซ็นเซอร์จริงและสวิตช์จำลอง โดยขาที่ไม่ได้ต่อจะอ่านเป็นไม่แตะ ไม่ต้องลงไลบรารีเพิ่ม เซ็นเซอร์นี้ตรวจการสัมผัสหรือแตะค้าง ไม่ได้แยกทิศทางหรือความแรงของการลูบ หากซ่อนใต้เปลือกหัวให้ลองความหนาและความไวกับวัสดุจริงก่อนประกอบ

## แอนิเมชันและการทำงานพร้อมกัน

วาด Procedural Animation ทุก 16,667 µs (เป้าหมาย 60 FPS) ด้วย `fillRoundRect`, `fillCircle`, `fillTriangle` และสีดำตัดขอบ ดวงตาเป็นทรงทึบ ไม่มีวงกลมหรือจุดไฮไลต์ด้านใน ทั้งตาปกติและตาหัวใจ ไม่มี `delay()`, `delayMicroseconds()` หรือ `pulseIn()` ในเฟิร์มแวร์

HC-SR04 เริ่มวัดทุก 80 ms และใช้ interrupt จับเวลา ECHO ส่วนการอ่านสัมผัสและการขยับคอทำงานร่วมกันใน loop โดยไม่รอให้แอนิเมชันเล่นจบ ESP32Servo ใช้ timer 0 สำหรับควบคุมเซอร์โว

I²C ใช้ 400 kHz ตามปกติ การส่งภาพเต็ม 1,024 bytes ทุกเฟรมจะใช้เวลามากกว่า 23 ms จึงใช้บัฟเฟอร์ภาพที่กำลังส่งแยกจากภาพที่กำลังวาด และส่งเฉพาะช่วง pixel ที่เปลี่ยนไป ครั้งละไม่เกิน 120 bytes (ประมาณ 3 ms) ให้ loop กลับไปบริการอินพุตระหว่างช่วงส่งข้อมูล จังหวะ I²C แต่ละช่วงยังเป็น synchronous ตาม Wire API

Serial รายงาน `FPS draw` (อัตราสร้างภาพ) และ `OLED` (อัตราที่ส่งภาพเสร็จ) รวมทั้ง `skipped` (ภาพที่ถูกแทนด้วยภาพใหม่ก่อนเริ่มส่ง) ค่า OLED อาจต่ำกว่า 60 ขณะเปลี่ยนอารมณ์หรือเมื่อ Simulator ทำงานช้า จึงไม่ใช้ตัวเลขจังหวะ render อ้างเป็น FPS จริงของจอ

## การต่อวงจรจำลอง

| อุปกรณ์ | ขาอุปกรณ์ | ESP32 |
| --- | --- | --- |
| SSD1306 128×64 (0x3C) | SDA / SCL | GPIO 21 / GPIO 22 |
| SSD1306 | VCC / GND | 3V3 / GND |
| Servo | PWM | GPIO 18 |
| Servo | V+ / GND | 5V / GND |
| HC-SR04 | TRIG / ECHO | GPIO 5 / GPIO 19 |
| HC-SR04 | VCC / GND | 5V / GND |
| สวิตช์จำลอง TTP223 OUT | 2 (ขากลาง) | GPIO 4 (`INPUT_PULLDOWN`) |
| สวิตช์จำลอง TTP223 OUT | 1 (ซ้าย) / 3 (ขวา) | GND / 3V3 |

สายแดงคือไฟเลี้ยง สายดำคือกราวด์ ส่วนสัญญาณใช้สีแยกกัน อุปกรณ์ทุกชิ้นต่อกราวด์ร่วมกับบอร์ด เมื่อประกอบจริงให้ใช้ TTP223 แทนสวิตช์ตามตารางในหัวข้อเซ็นเซอร์จริง ไม่ต้องต่อปุ่มหรือลำโพง

## เมื่อนำไปใช้กับฮาร์ดแวร์จริง

วงจรจำลองต่อ ECHO ตรงเข้า GPIO 19 ตามโมเดล Wokwi แต่ HC-SR04 จริงส่ง ECHO ระดับ 5V จึงต้องลดเหลือประมาณ 3.3V ก่อนเข้าขา ESP32 เช่น ECHO → ตัวต้านทาน 1 kΩ → GPIO 19 และ GPIO 19 → ตัวต้านทาน 2 kΩ → GND

เซอร์โวจริงควรใช้แหล่งจ่าย 5V ที่จ่ายกระแสพอสำหรับมอเตอร์ และต่อกราวด์ร่วมกับ ESP32 ปรับช่วง pulse ของ `neck.attach()` และมุมหลบใน `serviceNeck()` ให้ตรงกับขอบเขตกลไกจริง

## ตรวจสอบหลังแก้ไข

1. รัน `pio run -e esp32dev` แล้วเปิด Wokwi ใหม่
2. เริ่มสวิตช์ซ้าย ระยะ 100 cm: ต้องเป็น Idle และ `Pet=off` ไม่มีวงกลมด้านในตา
3. เปลี่ยนระยะเป็น 30 cm และ 10 cm: ต้องได้ Happy และ Angry ตามลำดับ เซอร์โวยังตอบสนอง
4. ที่ระยะ 10 cm เลื่อนสวิตช์ขวา: ต้องเปลี่ยนเป็น Love และ `Pet=touched` แม้ยังอยู่ใกล้ ตาหัวใจไม่มีวงกลมไฮไลต์
5. เลื่อนกลับซ้าย: `Pet=off` แต่ Love ยังอยู่ประมาณ 1.2 วินาที แล้วกลับ Angry
6. เปลี่ยนเป็น 100 cm ไม่แตะหรือขยับระยะต่ออีก 10 วินาที: ต้องง่วง จากนั้นแตะอีกครั้งต้องตื่นเป็น Love
7. ยืนยันว่าไม่มี buzzer ในวงจรและไม่มีเสียงทุกโหมด ส่วนการตรวจความไว TTP223 ต้องทดสอบบนฮาร์ดแวร์จริง

## ไฟล์และเวอร์ชันไลบรารี

- `platformio.ini`: environment `esp32dev` และไลบรารีที่จำเป็น
- `src/main.cpp`: โค้ดทั้งหมดของเฟิร์มแวร์
- `diagram.json`: ตำแหน่งอุปกรณ์และการต่อวงจร Wokwi
- `wokwi.toml`: ตำแหน่งไฟล์เฟิร์มแวร์สำหรับ Simulator

ล็อก ESP32Servo ที่ 0.13.0 เพื่อรองรับ Arduino-ESP32 2.x ที่มากับแพลตฟอร์ม `espressif32` ทางการ
