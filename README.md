# Desk Companion Bot

หุ่นเพื่อนบนโต๊ะสำหรับ ESP32 / Arduino / PlatformIO ใช้ **IPS TFT 1.3 นิ้ว ST7789 240×240 ผ่าน hardware SPI** ลูบหัวด้วย TTP223 ใช้ดวงตาสื่ออารมณ์โดยไม่มีปาก ไม่มีเสียง และไม่มีรูม่านตาหรือจุดกลมภายในตา

![ห้าอารมณ์จาก renderer และ Adafruit GFX ที่เฟิร์มแวร์ใช้จริง](docs/eye-preview.png)

![ตัวอย่างลูบหัวจาก renderer ของเฟิร์มแวร์](docs/petting-preview.gif)

ภาพและ GIF วาดจากโค้ดจริงบนคอมพิวเตอร์ โดยป้อนสถานะตัวอย่าง ไม่ใช่วิดีโอจากบอร์ดหรือหลักฐาน FPS ของจอจริง

## Build และจำลอง

ติดตั้ง PlatformIO IDE และ Wokwi Simulator ใน VS Code แล้วรัน:

```sh
pio run -e esp32dev -e esp32sim
```

| Environment | จอ | ใช้กับ |
| --- | --- | --- |
| `esp32dev` | ST7789 240×240 แบบ 7 ขา | เครื่องจริง |
| `esp32sim` | ILI9341 240×320 | Wokwi เท่านั้น |

โปรไฟล์เริ่มต้นของ PlatformIO คือ `esp32dev` เพื่อให้ปุ่ม Upload ใช้เฟิร์มแวร์จอจริง อัปโหลดด้วย `pio run -e esp32dev -t upload` เปิด Serial ที่ 115200 baud ด้วย `pio device monitor`

สำหรับ Wokwi ให้ build `pio run -e esp32sim` แล้วกด F1 → **Wokwi: Start Simulator** ไฟล์ `wokwi.toml` ชี้ไปที่ `.pio/build/esp32sim/firmware.bin` และ `firmware.elf` ต้อง build และเริ่ม Simulator ใหม่หลังแก้โค้ด

หลังเริ่มต้องเห็น `Display=READY` และค่า `FPS draw` / `TFT` ขยับจากศูนย์หลังผ่านช่วงเริ่มต้น หากเคยใช้รุ่นที่ขึ้น `RGB565 canvas allocation failed` ให้ build โปรไฟล์ `esp32sim` ใหม่ก่อนเริ่มจำลอง รุ่นนี้ใช้บัฟเฟอร์ที่จองไว้ตั้งแต่ build เพื่อแก้จอดำจากการจองหน่วยความจำก้อนใหญ่ก่อน `setup()`

Wokwi ใช้ **ILI9341 เป็นตัวแทนแสดงภาพสีด้วยไดรเวอร์ของมันเอง** ไม่ใช่โมเดล ST7789 และไม่ใช้ยืนยันการเริ่มทำงานหรือความเร็วของจอจริง ไม่ต้องซื้อ ILI9341 ใบหน้าขนาด 240×160 อยู่กึ่งกลางทั้งสองจอ พื้นที่ดำรอบหน้าต่างกันตามขนาดจอ

คลิก HC-SR04 เพื่อเปลี่ยนระยะ เริ่มที่ 100 cm สวิตช์ **TTP223 OUT (simulation)** เลื่อนขวา = แตะ HIGH เลื่อนซ้าย = ปล่อย LOW เป็นการจำลองสัญญาณ OUT ไม่ใช่ความจุไฟฟ้าของเซ็นเซอร์จริง

## ต่อจอ ST7789 จริง แบบ 7 ขา

| ขาบนจอ | ESP32 |
| --- | --- |
| GND | GND ร่วม |
| VCC | 3V3 |
| SCL / SCK / CLK | GPIO 14 |
| SDA / DIN / MOSI | GPIO 23 |
| RES / RST | GPIO 33 |
| DC / D-C | GPIO 26 |
| BLK / BL | 3V3 เพื่อเปิด backlight |

**SDA/SCL ของจอนี้เป็น SPI ไม่ใช่ I²C** ไม่ใช้ GPIO 21/22 ของ OLED เดิม รุ่น 7 ขาไม่มี CS จึงตั้ง `TFT_CS = -1` ถ้าใช้รุ่น 8 ขาที่มี CS ให้ต่อ CS → GPIO 27 และเปลี่ยน `TFT_CS` ในส่วนเครื่องจริงเป็น `27`

ใช้ไฟและลอจิก 3.3V ตามโมดูลราคาประหยัดนี้ ไม่อ้างสเปก 5V ของ breakout ยี่ห้ออื่นแทน ใช้สาย SPI สั้นและกราวด์ร่วม GPIO 14/23 ถูกเลือกเพื่อไม่ชน GPIO 18 ของเซอร์โวและ GPIO 19 ของ ECHO

หากจอดำหรือภาพผิด ให้ตรวจสายและไฟก่อน แล้วปรับค่าต้น `src/main.cpp` ตามโมดูล:

- `TFT_SPI_HZ`: เริ่ม 40 MHz ลดเป็น 20 MHz หากภาพแตกหรือสายยาว
- `TFT_SPI_MODE`: เริ่ม `SPI_MODE0` โมดูลไม่มี CS บางรุ่นอาจต้องใช้ `SPI_MODE3`
- `TFT_INVERT`: เริ่ม `true` สลับเป็น `false` หากโมดูลต้องการการกลับสีต่างกัน

SPI ไม่มีการตอบรับว่าจอแสดงภาพสำเร็จ ต้องตรวจภาพจริงด้วย ไม่ใช้ Serial ที่ทำงานปกติยืนยันว่าจอต่อถูก

## เซ็นเซอร์และเซอร์โว

| อุปกรณ์ | ขา | ESP32 |
| --- | --- | --- |
| TTP223 | VCC / GND / OUT | 3V3 / GND / GPIO 4 |
| HC-SR04 | TRIG / ECHO | GPIO 5 / GPIO 19 |
| HC-SR04 | VCC / GND | 5V / GND |
| Servo | PWM | GPIO 18 |
| Servo | V+ / GND | แหล่งจ่าย 5V สำหรับมอเตอร์ / GND ร่วม |

ตั้ง TTP223 เป็น **Direct / Momentary + Active HIGH** ไม่ใช้ Toggle ตรวจจัมเปอร์ตามโมดูล และปล่อยแผ่นสัมผัสว่างอย่างน้อย 1 วินาทีตอนเปิดเครื่อง โค้ดใช้ `INPUT_PULLDOWN` และกรองสัญญาณนิ่ง 25 ms ตรวจการแตะ/แตะค้าง ไม่แยกทิศทางหรือความแรงการลูบ

HC-SR04 จริงส่ง ECHO 5V ต้องลดระดับก่อนเข้า ESP32 เช่น ECHO → R 1 kΩ → GPIO 19 และ GPIO 19 → R 2 kΩ → GND ส่วน Wokwi ต่อ ECHO ตรงตามโมเดลจำลอง

เซอร์โวใช้แหล่งจ่ายที่จ่ายกระแสพอและกราวด์ร่วม ปรับช่วง pulse ของ `neck.attach()` และมุมหันหนีตามกลไกจริง จอไม่ได้ใช้ขาทัช ไม่มีลำโพงหรือ buzzer

จอ ILI9341 ใน Wokwi ต่อ MOSI → 23, SCK → 14, D/C → 26, CS → 27, VCC → 3V3 และ GND ร่วม ไม่ต่อ MISO ส่วน RST และ backlight ไม่ได้จำลองตามเอกสาร Wokwi

## สีหน้าและพฤติกรรม

| เงื่อนไข | ภาพใบหน้า | คอ |
| --- | --- | --- |
| Idle: มากกว่า 50 cm | ตาทึบสีฟ้ามินต์ กลอกตา หายใจและกะพริบ | ตามสายตาเล็กน้อย |
| Sleepy: ไม่มีปฏิสัมพันธ์ 10 วินาที | ตาปรือสีม่วงหม่น มี Zz ลอยขึ้น | กลับ 90° |
| Happy: 15–50 cm รวมขอบ | ตายิ้มสีทอง แก้มอุ่น หัวใจเล็กและดาวข้างตา | ส่ายนุ่มนวล |
| Angry: น้อยกว่า 15 cm | ตาคมสีคอรัล สั่นเบา ๆ ไม่มีตายิ้ม แก้ม หรือหัวใจจากอารมณ์ก่อนหน้า | หันหนี 180° |
| Love: สัมผัส สำคัญสูงสุด | ตาทรงเดิมค่อย ๆ หรี่ยิ้มสีชมพู เอนหน้าและมีแก้ม | ค่อย ๆ หันใกล้ 98° ขยับช้า ๆ ±3° |
| ไม่มี echo ภายใน 30 ms | Idle / no echo ยกเว้น Love ซึ่งยังสำคัญกว่า | ตามโหมดปัจจุบัน |

Love ค้าง 1.2 วินาทีหลังปล่อยแล้วค่อย ๆ คลายท่า การเอนหน้าเป็นภาพบนจอ เซอร์โวหนึ่งตัวใช้หันคอ การเข้าใกล้ภายใน 50 cm ลูบหัว หรือเปลี่ยนระยะจากจุดอ้างอิงอย่างน้อย 4 cm ปลุกจากอาการง่วง

ทุกโหมดไม่มีปากเสี้ยววงกลม ใช้ทรงตา สี และการขยับสื่ออารมณ์แทน สถานะ Angry คุมตาทันที ไม่รอ `angryBlend` เกิน 0.5 และระงับตายิ้ม หัวใจ แก้มจากค่า Happy/Love ที่กำลังจางออก

## ความลื่นและหน่วยความจำ

วาดด้วย Adafruit GFX ลง indexed canvas สองชุด ชุดละ 240×160 = 38,400 bytes รวม **76,800 bytes ที่จองคงที่ใน RAM ตั้งแต่ build** ไม่ใช้ `malloc()` จองบัฟเฟอร์ก้อนใหญ่ใน global constructor จึงไม่มีเงื่อนไขจอถูกปิดจากการจองก้อนนั้นล้มเหลวแบบรุ่นก่อน ตัวเลข RAM ตอน build รวมบัฟเฟอร์ทั้งสองแล้ว

แต่ละเฟรมมี palette 5 สี เก็บเป็น RGB565 เต็มความแม่นยำ รวม 20 bytes สำหรับสองเฟรม ก่อนส่งจอขยายดัชนีสีครั้งละ 8 แถวลงบัฟเฟอร์ RGB565 3,840 bytes รวมพื้นที่ pixel / palette / ส่งภาพ **80,660 bytes** บวก metadata เล็กน้อย ความละเอียด สี และเอฟเฟกต์เดิมคงอยู่ ไม่ได้ลดเป็นสี RGB332

พื้นที่ใบหน้าเคลื่อนไหว 240×160 อยู่กลางจอ 240×240 พื้นที่ดำด้านบน/ล่างล้างครั้งเดียว ภาพที่กำลังส่งไม่ถูกแก้ ขณะอีกบัฟเฟอร์วาดเฟรมใหม่ จึงไม่เกิดเฟรมดำจากการ clear จอแล้ววาดทีละชิ้น

เปรียบเทียบทั้งดัชนีและ palette กับภาพที่ส่งครบแล้วก่อนนำบัฟเฟอร์เก่ากลับมาวาด จึงยังส่งสีใหม่แม้ทรงตาไม่เปลี่ยน ส่งเฉพาะแถบที่เปลี่ยนผ่าน hardware SPI ครั้งละ 8 แถว = 3,840 bytes เวลาบิตบนสายประมาณ **0.77 ms ที่ 40 MHz** ต่อช่วง กรณีเปลี่ยนทั้งพื้นที่หน้าคือประมาณ 15.36 ms ยังไม่รวมเวลาวาด แปลงสี เรียกไลบรารี และบริการอินพุต HC-SR04 จับ ECHO ด้วย interrupt เริ่มวัดทุก 80 ms และไม่แทรก SPI/Serial ระหว่าง TRIG 10 µs

เป้าหมายสร้างภาพ 60 Hz แต่ **ไม่รับรองจอจริง 60 FPS** ต้องวัดกับโมดูลและสายจริง การส่งแถบไม่ได้ซิงก์ TE ของจอ จึงอาจมีรอยฉีกขณะเคลื่อนไหว Simulator ไม่ใช้วัดความเร็วฮาร์ดแวร์

Serial แสดง `FPS draw` (สร้างภาพ), `TFT` (ภาพเป้าหมายที่แสดงครบ รวมภาพที่เหมือนเดิมจนไม่ต้องส่งซ้ำ), `skipped` (เฟรมใหม่แทนเฟรมที่ยังไม่เริ่มส่ง) และ `SPI max` (เวลาส่งช่วงที่นานที่สุดตั้งแต่เปิดเครื่อง) ค่า TFT เป็นอัตราภาพเป้าหมายที่สำเร็จ ไม่ใช่อัตรา refresh ภายในแผง LCD

## ตรวจสอบ

```sh
pio run -e esp32dev -e esp32sim
python tests/run_render_checks.py
```

Host test ใช้ **renderer และ Adafruit GFX ตัวเดียวกับเฟิร์มแวร์** ตรวจ 605 เฟรม Angry ระหว่างเปลี่ยนอารมณ์/กะพริบและค่า Happy/Love ค้าง ตรวจตายังมองเห็นและไม่มีภาพจากความรักแทรก รวมถึงบัฟเฟอร์อยู่ภายใน object, การเปลี่ยน palette, การขยายสี RGB565, ขอบเขตแถบภาพ และไม่มีปากทุกโหมด ไม่ใช้เฟรมเวิร์กทดสอบ

ต้องมี g++ C++11 ขึ้นไป หรือระบุ `--compiler` สำหรับ Windows ติดตั้งได้ด้วย `pio pkg install --global --tool platformio/toolchain-gccmingw32` ไฟล์ `tests/host` แทนเฉพาะชนิดข้อมูล Arduino ที่ GFX ต้องการ ไม่ได้จำลองบัสหรือฮาร์ดแวร์

สร้างภาพ/GIF ใหม่ด้วย `python tests/run_render_checks.py --preview` ต้องมี Pillow เพิ่มเติม

ตรวจใน Wokwi / เครื่องจริงต่อ:

1. ระยะ 100 cm ไม่แตะ: Idle สีฟ้า ไม่มีรูม่านตาหรือจุดกลมในตา
2. 30 cm → 10 cm: Happy → Angry ต้องมีตาโกรธตั้งแต่เฟรมแรกที่วาดสำหรับ Angry ไม่มีปากทั้งสองโหมด
3. แตะค้างที่ 10 cm: Love สีชมพูชนะระยะ ตายังทรงเดิมและกะพริบได้
4. ปล่อย: Love ต่อ 1.2 วินาที แล้วกลับ Angry ไม่มีรอยยิ้ม/แก้มค้าง ทำซ้ำและดูช่วงกะพริบ
5. 100 cm คงที่ 10 วินาที: Sleepy แล้วแตะปลุก
6. ตรวจ `Display=READY` แล้วค่า FPS ขยับจากศูนย์ เครื่องจริงให้ตรวจสี การต่อขา ค่า TFT / SPI max ทุกโหมด และเซอร์โวยังตอบสนองระหว่างส่งจอ

ทดสอบ runtime ใน Wokwi for VS Code แล้ว: เริ่มแสดงตาได้, Idle/Sleepy, แตะเป็น Love และปล่อยมือที่ระยะ 10 cm กลับเป็น Angry โดยไม่มีปากและไม่มีรอยยิ้มค้าง การทดสอบนี้ยังไม่ยืนยันการเริ่มจอ ST7789 จริงหรือ FPS ของฮาร์ดแวร์

## ไฟล์และการย้อนกลับ

- `src/main.cpp`: อินพุต อารมณ์ เซอร์โว SPI และสถิติ

- `platformio.ini`: ไลบรารีล็อกเวอร์ชันและโปรไฟล์จริง/จำลอง
- `diagram.json`, `wokwi.toml`: วงจรตัวแทนและเฟิร์มแวร์จำลอง
- `tests/run_render_checks.py`, `tests/face_render.cpp`: ตรวจภาพและสร้าง preview
