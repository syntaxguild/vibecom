# Assembly fit audit — Mochi v0.5

วันที่ตรวจ: 2026-10-16 — **ยังไม่พร้อมสั่งพิมพ์ทั้งชุดเพื่อประกอบใช้งาน**

ตรวจไฟล์ BLEND ที่ส่งอยู่จริงด้วย Blender Boolean intersection 61 คู่ ระหว่าง envelope อุปกรณ์กับชิ้นพิมพ์ และระหว่างอุปกรณ์ต่างตระกูล ผลตัวเลขเต็มและ SHA-256 ของ BLEND/สคริปต์อยู่ใน [assembly-audit.json](assembly-audit.json) ไม่มีการแก้รูปทรงหรือ STL ในงานตรวจรอบนี้

## พบจาก geometry ที่มีอยู่แล้ว

| จุด | หลักฐาน | ผล |
| --- | --- | --- |
| ESP32 PCB กับตัวถัง | ปริมาตรซ้อน 68.4283 มม.³ บริเวณเสาฝาฐานด้านหลัง | ต้องย้ายเสาหรือบอร์ดและตรวจทางใส่ใหม่ |
| แถบยึด SG90 กับตัวถัง | envelope แถบยึดซ้อนผนัง 48.1107 มม.³ | ต้องตรวจทรง tab จริงและจัดตำแหน่ง/ช่องหลบ |
| ขนาดภายนอก | วัดขอบเขตชิ้น STL ใน BLEND | 80 × 66 × 100.8 มม. ไม่รวมเครื่องหมายทัชตกแต่ง |
| ทางใส่ PCB ToF | ยกผ่านฐานที่ Y=-18 แล้วเลื่อนมาหน้า ตรวจ 9 ตำแหน่ง | ไม่ชนตัวถังใน 9 ตำแหน่งที่สุ่มตรวจ เฉพาะ PCB เปล่า ไม่รวมสาย/ขาเสียบ |

การซ้อนของ envelope เป็นหลักฐานว่าต้องทบทวน ไม่ใช่ปริมาตรชนของอุปกรณ์จริงทุกส่วน: โมเดล SG90 ยังไม่รวมรูและรายละเอียด tab จริง ส่วน PCB ESP32 ที่ชนเสาฝาฐานไม่มีรูยึดอ้างอิง ณ จุดนั้น

## ตรวจจาก drawing ผู้ผลิตและพื้นที่สำรอง

- **ESP32:** [drawing Espressif](https://dl.espressif.com/dl/schematics/esp32_devkitc_v4_dimensions.pdf) ระบุ 48.26 มม. จากปลาย USB ถึงขอบเริ่มเสาอากาศ และส่วนเสาอากาศยื่นต่ออีก 6.04 มม. รวมความยาวประมาณ **54.30 มม.** ส่วนยื่นกว้าง 18 มม. โมเดลเดิมใช้ 48.26 มม. เป็นความยาวทั้งหมดจึงสั้นไป เมื่อตรึงปลาย USB ไว้เดิมแล้วเพิ่มส่วนยื่นตาม drawing พบชนตัวถังอีก 54.9567 มม.³ ความหนา PCB 1.6 มม. ยังเป็นสมมติฐาน
- **LCD:** [drawing Waveshare](https://files.waveshare.com/upload/6/6d/2inch_LCD_Module_2D_Drawing.pdf) ยืนยัน PCB 58 × 35 มม. และระยะรู 53 × 30 มม. จึงยืนยันระยะรูที่เคยทำเป็น provisional ได้ แต่ยังต้องเทียบตำแหน่ง active area และ stack จริง ขนาด backlight 47.83 × 34.60 มม. เมื่อลองวาง envelope ลึก 4 มม. หลังหน้าจอตามตำแหน่งภาพเดิม พบชนเปลือกหัว 303.1749 มม.³ **ความลึกและตำแหน่งของ proxy นี้เป็นสมมติฐาน** ไม่ใช่ข้อสรุปว่าชิ้นจริงชนเท่านี้ ต้องออกแบบช่องหลังกรอบและ stack ให้ครบ
- **Header ESP32:** ทดลองพื้นที่หัวเสียบสูง 8.5 มม. ที่แถวล่าง พบชนฐาน 86.5473 มม.³ ยังไม่ได้เลือกรุ่นหัวเสียบ จึงเป็นข้อจำกัดของสมมติฐานนี้ ห้ามสรุปว่าสายจัมเปอร์ทุกแบบใส่ได้
- **ToF:** [drawing Pololu](https://www.pololu.com/file/0J1194/vl53l0x-vl53l1x-vl53l3cx-vl53l4cd-carrier-dimension-diagram.pdf) ยืนยัน PCB 12.7 × 17.8 × 1.02 มม. แต่ศูนย์ package ใน drawing อยู่ 6.9 มม. จากขอบซ้าย ไม่ใช่ศูนย์ PCB ที่ 6.35 มม. จึงมี offset 0.55 มม. ซึ่งต้องนำเข้าแบบและตรวจแนวแสงใหม่ รายงานเดิมยิงรังสีจากศูนย์สมมติ จึงยังใช้ยืนยันแนวแสงจริงไม่ได้
- **Servo:** [TowerPro](https://towerpro.com.tw/product/sg90-7/) ยืนยันเคส 23 × 12.2 × 29 มม. แต่โมเดลปัจจุบันยังไม่มี spline, horn, รู tab และหัวสกรูจริงครบ จึงยังรับรองแกนหมุนและการเข้าถึงสกรูไม่ได้
- **Touch:** [DFRobot DFR0030](https://wiki.dfrobot.com/dfr0030/) ยืนยัน PCB 22 × 30 มม. ยังไม่มีมิติ connector/ความสูงอุปกรณ์เพียงพอให้รับรอง fit ทั้งชุด

## สิ่งที่ต้องทำก่อนส่งพิมพ์ครบชุด

1. แก้ outline ESP32 รวมเสาอากาศ จัดบอร์ดและเสาฝาฐานให้ไม่ชน พร้อมเช็กช่อง USB ตามตำแหน่งใหม่
2. แก้แถบยึด servo และวาง horn/หัวสกรูให้ครบก่อนยืนยันการหมุน
3. จัด stack LCD, ช่องหลังกรอบ และระยะสายจาก connector ให้ครบ
4. ปรับ offset เซ็นเซอร์ ToF ตาม drawing และเผื่อบัดกรี/connector ที่เลือกจริง
5. กำหนดหัวเสียบ/วิธีเดินสายและสกรูจริง แล้วตรวจทางใส่และพื้นที่ไขควง จากนั้นพิมพ์เฉพาะจุดยึดมาทดลอง

ยังไม่มีเส้นทางสายไฟที่ออกแบบครบทั้งระบบ ไม่มีการรับรองรัศมีงอสายหรือ connector ทุกชนิด ไม่มีการวัดอะไหล่จริง และไม่ได้ทดสอบความไวทัชผ่านพลาสติกจริง การตรวจนี้ช่วยชี้ปัญหาที่แก้ได้ในคอมก่อนเสียค่าพิมพ์ ไม่ใช่ใบรับรองพร้อมผลิต

รันซ้ำได้โดยเปิด terminal ที่รากโปรเจกต์:

```sh
blender --background --python-exit-code 1 --python mechanical/audit_assembly.py
```

ผล `print_ready: false` เป็นสถานะการทบทวนรอบนี้ ไม่ใช่ตัวตัดสินอัตโนมัติที่เปลี่ยนเป็น true เมื่อไม่มีปริมาตรซ้อน
